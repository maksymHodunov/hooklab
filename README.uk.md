# HookLab: хуки для модифікацій

[English version](README.md)

HookLab бере скрипт креативу-переможця і за хвилину пропонує нові перші 3 секунди для модифікацій: візуал, першу фразу і текст на екрані. Тіло й CTA лишаються як у переможця. Дизайнер клацає на варіанти, які бере в роботу, за потреби перегенеровує окремі з них («драматичніше», «коротше», власна нотатка) і завантажує бриф у CSV. Моделі Claude і GPT підключені через OpenRouter, їх можна перемикати у формі. Інтерфейс доступний англійською та українською.

MVP до домашнього завдання з MarTech для вигаданого DTC-бренду SockLock (магнітні шкарпетки, які не губляться в пральці).

**Яку проблему закриває.** Дизайнери витрачають приблизно половину з 3 годин на модифікацію на ручне переписування хуків. Щоб подвоїти spend з $400k до $800k на місяць, потрібно ~500 модифікацій на місяць, а команда робить 240. За оцінкою, звільнений час дає +$55k EGP на місяць у базовому сценарії.

## Запуск

Потрібен Node.js 20.12 або новіший.

```bash
npm install
npm start
```

Відкрийте <http://localhost:3000>. `npm start` збирає вебзастосунок і запускає сервер.

Без ключа HookLab працює в **демо-режимі**: три тестові переможці й заздалегідь підготовлені приклади результату, модель не викликається. Щоб генерувати для будь-якого скрипту, додайте ключ OpenRouter:

```bash
cp .env.example .env
# впишіть OPENROUTER_API_KEY у .env
npm start
```

### З термінала

```bash
npm run cli -- data/winners/w01-laundry-monster.md --model opus --count 5 --angles pain,humor --lang uk
```

`--model` приймає повний ID або коротку назву: `sonnet`, `opus`, `sol`, `astra`. `--lang` задає мову виводу CLI (`en` або `uk`, за замовчуванням з `HOOKLAB_LANG`, інакше англійська). Команда друкує варіанти й зберігає бриф у `out/brief-<переможець>-<запуск>.csv`.

### Розробка вебзастосунку

```bash
npm run serve        # API-сервер на :3000
npm run dev          # Vite з гарячим перезавантаженням, проксіює /api на :3000
```

## Як користуватися

1. Виберіть приклад або вставте свій скрипт (краще з таймкодами: хук, тіло, CTA) і задайте ID переможця.
2. Виберіть модель і кількість варіантів: швидкі кнопки 5, 10, 15 або своє число до 30. За потреби додайте кути й нотатки. Під кнопкою «Згенерувати» видно орієнтовну вартість запуску.
3. Клацніть на картку, щоб вибрати її. Щоб доопрацювати варіант, натисніть **Перегенерувати** на картці: виберіть швидкі правки (драматичніше, смішніше, коротше, простіше, сильніший візуал, більше UGC, інший кут) та/або напишіть нотатку. Нова версія отримує `mod_id` із суфіксом `v2`, `v3`…
4. Завантажте бриф. `mod_id` (наприклад, `W01-7c0060-H03`) додавайте в назву креативу в Meta, щоб результати з UA-звіту можна було зіставити з конкретним хуком.

Перемикач мови в шапці змінює лише інтерфейс. Сам бриф (хуки, візуал, пояснення, попередження) завжди пишеться мовою скрипта переможця: англійський скрипт дає англійський бриф, німецький — німецький.

## Моделі

| Модель | ID в OpenRouter | Ціна за 1M токенів (вхід / вихід) | Виміряна вартість |
|---|---|---|---|
| Claude Sonnet 5.5 (за замовчуванням) | `anthropic/claude-sonnet-5.5` | $2 / $10 | 5 варіантів — $0.04, 10 — $0.05, 30 — $0.10 (80 с) |
| Claude Opus 5.5 | `anthropic/claude-opus-5.5` | $4 / $20 | 5 — $0.07, 15 — $0.12 |
| GPT-6.1 Sol | `openai/gpt-6.1-sol` | $2 / $10 | 5 — $0.02, 15 — $0.04 |
| GPT-6 Astra | `openai/gpt-6-astra` | $10 / $50 | 5 — $0.12, 15 — $0.25 |

Перегенерація одного варіанта на Claude Sonnet 5.5 займає ~10 с і коштує ~$0.02. Щоб додати модель, допишіть рядок у `src/models.ts`.

### Оцінка вартості

Перед запуском під кнопкою «Згенерувати» видно орієнтовну вартість, а у вікні перегенерації — вартість одного варіанта. Після запуску поруч із фактичною вартістю показується й оцінка, щоб їх можна було порівняти.

Як рахується (`src/estimate.ts`):

1. **Вхідні токени** = довжина промпту (системний промпт + скрипт + налаштування) ÷ символів на токен для моделі.
2. **Вихідні токени** = база + кількість варіантів × токени на варіант. Ці числа для кожної моделі виміряні на тестових запусках від 5 до 30 варіантів і записані в `src/models.ts`.
3. **Вартість** = токени × ціна моделі, діапазон від −25% до +35%.
4. **Самокалібрування:** після кожного живого запуску в журнал пишуться оцінка і фактична вартість від OpenRouter. Оцінку множимо на медіану їхнього співвідношення за останні 10 запусків цієї моделі, тож вона з часом підлаштовується під реальні дані.

На тестових запусках оцінка відхилялася від фактичної вартості на 0–3%.

## Як це працює

```
скрипт переможця ─┐
гайдлайни бренду ─┼─> промпт ─> OpenRouter ─> Claude / GPT (structured output за zod-схемою) ─> варіанти H01…H30
модель, кути     ─┘                                                                              │
          ↻ перегенерація одного варіанта: поточна версія + швидкі правки + нотатка ─> H03v2      │
                     out/runs/<запуск>.json        <─────────────────────────────────────────────┤
                     out/usage-log.jsonl (метрики) <─────────────────────────────────────────────┤
                     бриф CSV для дизайнерів       <─────────────────────────────────────────────┘
```

| Шлях | Що робить |
|---|---|
| `src/prompt.ts` | Системний промпт (що таке модифікація, вимоги до варіантів, кути, обмеження Meta і бренду), промпт перегенерації і швидкі правки |
| `src/schema.ts` | Zod-схеми відповідей. З них генерується JSON Schema для structured outputs, ними ж перевіряються відповіді моделей і демо-приклади |
| `src/models.ts` | Список моделей для форми і CLI, їхні ціни й коефіцієнти для оцінки вартості |
| `src/estimate.ts` | Оцінка вартості до запуску і її самокалібрування за фактичними запусками |
| `src/generate.ts` | Виклик OpenRouter, генерація набору, перегенерація одного варіанта, ID і версії, вартість, зрозумілі помилки |
| `src/i18n.ts` | Повідомлення сервера й вивід CLI англійською та українською |
| `src/server.ts` | HTTP-сервер без фреймворків: віддає вебзастосунок і `/api/generate`, `/api/regenerate`, `/api/estimate`, `/api/export`, `/api/winners`, `/api/status` |
| `src/cli.ts` | Генерація з термінала |
| `src/store.ts` | Збереження запусків і журнал подій для метрик |
| `src/csv.ts` | Бриф у CSV |
| `web/` | React + Vite + Tailwind + shadcn/ui (пресет `b1G2mZFZY`), тексти інтерфейсу в `web/src/lib/i18n.tsx` |
| `data/` | Гайдлайни бренду, 3 тестові переможці та їхні демо-приклади. Усі дані вигадані |

Запит іде з `provider.require_parameters: true`, тому OpenRouter направляє його лише до провайдерів, які підтримують structured outputs. Відповідь додатково перевіряється zod-схемою.

## Метрики успіху

| Метрика | Зараз | Ціль | Коли | Як міряємо |
|---|---|---|---|---|
| Час дизайнера на модифікацію | ~3 год | ≤ 2,2 год у пілоті, ~2 год після розгортання | 2 тижні / 3 місяці | Тайм-трекінг дизайнерів |
| Частка модифікацій пілотних дизайнерів, зроблених з HookLab | 0% | ≥ 50% | 2 тижні | `mod_id` у назвах креативів |
| Частка згенерованих варіантів, узятих у роботу | — | ≥ 30% | 2 тижні | `out/usage-log.jsonl`: `export.selected` / `generate.returned` |
| Перегенерацій на один узятий варіант | — | ≤ 1 | 2 тижні | `out/usage-log.jsonl`: події `regenerate` / `export.selected` |
| Модифікацій на місяць | 240 | 300 → 360 | 1 / 3 місяці | Звіт продакшну |
| Win rate модифікацій з HookLab | як в інших модифікацій | не нижчий | 4 тижні | UA-звіт, фільтр за `mod_id` |
| ROMI | 135% загальний | ≥ 130% на додатковому бюджеті, загальний ≥ 125% | щотижня | UA-звіт |
| Бізнес-ефект | — | +$55k EGP на місяць | 3 місяці | Додатковий spend × (ROMI − 100%) |

Пілот вважаємо успішним, якщо через 2 тижні виконано цілі за часом і часткою використання, а через 4 тижні win rate не впав. Тоді розгортаємо на всіх шістьох дизайнерів. Паралельно порівнюємо моделі: яка дає найбільшу частку взятих у роботу варіантів на долар.

## Наступна ітерація

Перші три пункти замикають цикл «переможець → хуки → таска → результат» без ручних вивантажень.

1. **Airtable.** Вибрані варіанти одразу стають тасками дизайнерам: бриф, `mod_id`, переможець, дедлайн. CSV лишається запасним варіантом.
2. **Meta.** Утиліта сама визначає переможців за ROMI і CPA, запускає для них генерацію і ставить таски в Airtable. Результати модифікацій підтягуються за `mod_id`, і найкращі хуки стають прикладами в промпті.
3. **Slack.** Алерти про нових переможців і кнопки для швидкого запуску генерації та інших автоматизацій.
4. **Локалізація для DE і FR.** Культурна адаптація хуків, а не дослівний переклад, плюс чекліст для перевірки носієм. Це розблокує європейські тести.

Далі, більша ставка:

5. **Генерація відео прямо в утиліті** з переходом у конструктор креативів: генерація зображень і відео, монтаж, субтитри.

## Обмеження MVP

- Немає доступу до Meta, Airtable і бекенду SockLock: на вході текст скрипту, на виході CSV.
- Демо-приклади підготовлені заздалегідь і показують формат результату. Справжня генерація і перегенерація працюють лише з ключем OpenRouter.
- Якість хуків оцінює дизайнер; автоматичної перевірки політик Meta поки немає.
- Запуски зберігаються локально в `out/`, без бази даних і авторизації.
